### 2.0.32（同一大类里，月粒度"有的能填、有的不能填"——目标月=当前月这 8 个）

上一版把「年月选择器」打通后，你这份诊断又暴露了最后一块：**8 个 `date-failed` 全是 `2026-10-xx`
（= 今天 10 月），其余目标月（9 月、11 月、6 月）全部填上了**。所以规则很干净——**目标月 = 当前月
就失败，其余都成**。

根因：这个年月选择器的月份列表里**缺「当前视图月」**（panelText：`1月…9月 11月 12月 本月`，
没有 10 月）。上一版遇到"目标月 = 当前月"时走 `ymsel-month:already`（假定已选中）+ 点「本月」提交，
结果在真机上**根本不落值**——「本月」只是导航不是提交（复刻页里我把它当提交，所以上一版自测全过、
真机仍翻车）。于是回读失败 → typing2 被拒 → 降级月再跑一遍还是同一个坑 → `date-failed`。

修复（`driveYmSelector` 提交后**回读裁决** + 新增 `driveYmViaIntermediate` 中间月跳板）：

1. 提交（点「本月」/「确定」）后不再"点了就算成"，而是**读外层输入框**（`trigHasYm`）确认
   真的落上 `YYYY-MM` 了；
2. 没落上 → 走「中间月跳板」：先点一个**别的月**（相邻月，必然在列表里）提交出中间值并关面板，
   再重开面板——此时视图/已选月已变成中间月，**目标月回到列表里**，点它提交；
3. 面板没关就直接复用，关了就重开（`ymsel-reopen`）。

验证（用例 [42] 新增场景 C/D）：
- 场景 C（复刻"本月不落值"的真机行为）：`2026-10-02` → 中间月跳板 → 落 `2026-10`；
- 场景 D：真机模式 + 目标年≠当前年（`2025-09`）→ 仍一次点中 `2025-09`。

**回归**：selftest 51、dom-test 201（[42] 增至 8 条）、beisen 164、panel-test 59，共 **475** 条全通过。

### 2.0.31（16 个经历类日期 date-failed：年月选择器新形态）

你反馈"日粒度的都能填上，月粒度的都填不上"，并澄清了降级语义——**先在网页试完整日期（如
`2025-10-01`），成功就停；失败再降级到年月（`2025-10`）**。这条语义本就是现有链路的
L1 → L4.5 整链降级，本轮真正修的是：经历类（教育/实习/在校职务/在校实践）的起止时间
在真机上不是"点头部展开下拉"的年月面板，而是**另一种「年月选择器」形态**，旧代码两个模式都点不中。

诊断 JSON 里 16 个 `date-failed` 的 attempts 只暴露出两种失败模式：

1. **`ym-year:fail + ym-year-mismatch`**（目标年 ≠ 当前年）：旧 `driveYmPanel` 假设"点头部完整年月标题
   切年份视图"，但这个组件点头部不切视图，点年自然失败。
2. **`ym-year:ok + ym-month:fail`**（目标年 = 当前年）：旧代码点"年份入口"误切到年份视图；且**目标月 =
   当前月时，月份列表里根本没有这个月**（当前月已选中、不在可选列表里），点月必失败。

修复：新增 `driveYmSelector`（形态 2），在 `driveYmPanel` 失败后兜底：

- 读当前年月视图 → `pickYear` 点目标年；
- **点标题里的「N月」标签切回月份视图**（这一步是关键的次生 bug：点完年停在年份视图，
  旧 `readView` 读到的月份与真实视图脱节，会误判 `ymsel-month:already`）；
- 目标月 = 当前月时列表缺它 → 直接走 already；否则点目标月；
- 点「本月」/「确定」提交，按 month 精度收工（`downgraded: 'month'`）。

验证（独立 dom 脚本 + 用例 [42]）：
- `2026-10-02`（目标月 = 当前月）→ 写入 `2026-10`；
- `2025-09-01`（目标年 ≠ 当前年）→ 写入 `2025-09`；
- `2026-06-24`（旧形态）→ 仍走 `driveYmPanel` 直接成功。

**回归**：selftest 51、dom-test 197（新增 [42] 年月选择器 4 条）、beisen 164、panel-test 59，共 **471** 条全通过。

### 2.0.28（三条：跨记录同步不提示重名 / 日期先日后月 / 身份证号多重试）

**① 自定义字段跨记录同步后，不再误报"同一条记录里有同名字段"**

上一版（2.0.26）本意是"按记录卡片分组、跨记录同名不算重名"，但实现里有个隐藏 bug：
分组键用了 `元素 + '|' + 名字` 的**字符串拼接**，而所有 `.record-card` 都是 `<section>`，
`toString()` 之后全变成同一个 `"[object HTMLElement]"`——等于跨记录分组根本没生效。
结果你在信息 1 加"年龄"、信息 2 自动同步出"年龄"后，两条仍会被判成重名并提示。

修法：分组键改成**用元素对象本身做 Map 键**（对象身份唯一，不再拼字符串），
并显式区分两类：
- **普通分类**：按记录卡片分组——跨记录同名（信息 1、信息 2 各有"年龄"）不算重名；
- **老的「自定义字段」分类**：字段名是全局的（跨记录同名会撞、只生效第一条）——仍全算一组，照旧提示。

同一条记录里手工输入两个同名，仍然照常提示（真重名没有放过去）。用例 [11] 覆盖。

**② 日期字段尝试顺序：先日粒度，回写不成功再月粒度，再不通才跳过**

这条**本来就已实现**，本轮做了核实确认，没有改代码。现链路是：

```
L1 原生日控件(日) → L2 框架模型 → L3a 键入(日) → L3 日历面板(日) → L4 键入(日)

### 2.0.24（网格布局站点：第二条经历整段不填 / 开始结束日期 / 学位 / 职位）

**① 根因找到了：你的网申站点是"网格布局"，每个字段独占一个父容器**

从前几轮的真实 DOM 看，这个站点的结构是：

```
.form-part-body
  └─ .fields-col × N          ← 一个字段一列
       └─ .form-item
            ├─ .form-item__title     ← 标签
            └─ .form-item__control   ← 控件
```

这就是为什么前三种切块方式**全都失效**：

| 切块方式 | 引入版本 | 在这个站点上为什么不成立 |
|---|---|---|
| ① 标签签名完全一致的父容器成组 | 2.0.15 | 每个 `.fields-col` 里只有 1 个字段，凑不出"一组签名相同的容器" |
| ② 两段共用一个父容器 → 按标签周期切 | 2.0.23 | 两段并不共用父容器，各字段各有各的 `.fields-col` |
| ③ 按父容器切，每块 ≥3 字段 | 2.0.21 | 每个父容器只有 1 个字段，永远达不到 3 |

三种都不成立 → 整段退化成 **1 个 block** → 第 2 段的字段全部和第一段撞槽
→ 被"同块去重"整段跳过 → 你看到的 **"填了两段，只渲染了第一段"**。

修法：**不看父容器，直接拿区块内按文档顺序排好的扁平字段列表做周期切分**。
标签序列能由一个长度 p 的子序列重复 k 次拼出来（允许 20% 噪声、允许各段字段数不等），
就切成 k 段。这条排在其余三种之前，因为它是唯一不依赖 DOM 嵌套关系的判据。

这一个根因同时解释了 **开始/结束日期、学位、职位**：它们都在"第 2 条"里，

### 2.0.23（新加那一段一条都没填 / 证件号码不填 / 名字含"日期时间"的字段）

**① 新加的那一段"一条信息都没填"——块切分的第三种形态**

前两轮修了"签名不同"和"点不动就连坐"，但漏了最常见的一种：**两段的字段挂在同一个父容器里**。

```

```

现象就是你说的"插件只完成添加动作，对应的信息没填写进去"。

修法：**按标签重复周期切块**。标签序列由同一个子序列重复 k 次组成时，切成 k 块。
周期从大到小找（12 个字段要切成 6+6，不是 3+3+3+3），也允许两段字段数不等（4+3），
但要求每段 ≥3 个字段、且各段字段数相差不超过 40%（否则"9+3"这类切法也会被误认）。

这条同时解释了 **职务 / 学位**：你在侧边栏里看到的是"家庭情况 2 / 教育经历 2"（第 2 条），
而页面第 2 段压根没渲染出来，你比对的是第 1 条——第 1 条的职务/学位本来就是空的。

**② 证件号码整行不填 —— 被我上一轮的位置配对漏掉了**

这一行是**复合控件**：`证件号码：[身份证 ▼] [请输入]`，1 个标签 + 2 个控件。
位置配对要求"标签数 == 控件数"，这里 1≠2 直接跳过 → 两个控件都拿到"证件号码" →
下拉抢走了 `personal.idNo` 这个槽（拿身份证号去选下拉，报 `option-no-match`），
真正的输入框反而被同槽去重跳过。

修法：1 个标签 + 多个控件时，**标签给"装值"的那个文本框**，前面的类型下拉明确不给标签。
反向验证时这条会报 `option-no-match`，一眼就能看出是下拉抢了槽。

**③ 名字含"时间/日期"的字段，一律按日期链路写**

你要求"只要字段名称包含时间、日期的，都按照出生日期的方式处理，且根据系统的粒度做适配"。
现在这是**规则**而不是逐个字段声明：任何字段（含自定义字段、含跨分类命中的字段），
只要**名字里带 `时间/日期/年月/生日/出生/入学/毕业/入职/离职/到岗/起止`** 且**值确实是日期**，
就强制走日期适配器——日历面板、多格式键入、按网页粒度自动降级到年月，全套一致。
所以「档案寄出日期 = 2025-07-01」这种你在自定义字段里手填的值，在只收年月的网页上会自动写成 `2025-07`。

**回归**：selftest 51、dom-test 122（新增 [19] 共父容器切块 5 条、[20] 证件号码复合控件 3 条、[21] 日期名提升 4 条、[22] 不等长切块 4 条）、beisen 164、panel-test 45。共 **382** 条全通过。反向验证三组均按预期失败，[19] 复现"第 2 段全空"、[20] 复现 `option-no-match`。

### 2.0.22（月粒度网页自动适配 / 所有多记录分类都能「添加」）

**① 网页只收年月（界面就是 `2026-10`）→ 自动把 `2025-10-01` 写成 `2025-10`**

这类站点没有"日"，完整日期怎么写都进不去。原来会判 `date-failed`，等于"资料越细越填不上"。
现在两层适配：

- **键入时把年月写法也当成正式格式试**：完整日期被拒后依次退到 `2025-10` / `2025/10` /
  `2025年10月` / `202510`，谁被接受用谁（报告里写 `typing:ok(2025-10)`）；
- **整条链降级重跑**（L4.5）：日粒度全链失败时，用 `2025-10` 把「原生 → 键入 → 面板」再走一遍，
  成功即收工，状态是**已填 + "网页只到年月，已按年月写入"**，不是失败。
  **网页只到年月不是错误，是站点能力**——这条是这一轮的核心立场。

顺手加了"格式记忆"：同一个站点上某种写法一次成功，后面的日期字段直接先试它，省掉 8 次试错。

**② 所有支持多条的分类都能自动「添加」**

`repeat.js` 本来就是遍历所有多记录分类（教育 / 实习 / 在校职务 / 在校实践 / 获奖 / 论文 /
语言能力 / 家庭情况 / 求职意向），但有三处让它实际只对教育经历有效：

1. **按钮搜索范围太窄**：只查区块容器和它父级一层 → 加**全文档兜底**（只认文案带分类名的，
   条件很强，不会点到别的分类）；
2. **纯图标按钮认不出**：`＋` 这类没有文字的按钮原来直接被丢弃 → 现在认 `＋/+ /⊕`，
   或 `add/plus` 类名 + `title/aria-label` 里有"添加"；
3. **一个分类失败就连坐全部**：原来点不动就 `break`，导致"教育经历加不上"把实习经历、
   在校职务全掐掉 → 现在只把这个分类标记跳过（`stuck`），其它继续。
   另外总轮次上限 8 → 20，够覆盖多个分类各加两三段。

顺带修掉两个误判：容器（`.card`）的文本里同时含分类名和"添加"，会被当成按钮点空；
单块区块的 `container` 就是 section 容器本身，导致"按钮必须在最后一块之后"永远不成立。

**回归**：selftest 51、dom-test 106（新增 [17] 月粒度 5 条、[18] 多分类添加 10 条）、beisen 164、panel-test 45。共 **366** 条全通过。反向验证：关掉月降级 → [17] 五条全挂且复现 `typing:value-rejected`；把 `stuck` 改回 `break` → 实习/在校职务两条挂。

### 2.0.21（四条反馈：学位不填 / 所有时间要能填 / 成绩补零 / 职务不填）

这一轮**没有逐条打补丁**，四条反馈背后只有两个结构性成因，另加一个"我们自己制造的失败"。

**成因一：一行两列的字段行 → 第二个字段永远填不上（对应「学位」和「职务」）**

网站把两个控件放进了同一个"字段行"容器（`<label>工作单位</label><input><label>职务</label><input>`）。
`labelTextsOf` 对**两个**控件都会返回 `["工作单位","职务"]` 两个标签，`pickLabel` 永远取第一个 →
两个控件都绑到 `family.company`，`职务` 那个槽没人用 → 前一个填好、后一个空着、还不报错。
「学历 / 学位」同理：两个下拉都绑到 `edu.degreeLevel`，写进「学位」下拉时选项对不上，于是停在「请选择」。

修法：同一容器里的**真实 label 节点数 == 控件数**时，按文档顺序一一配对（`pairLabelsByPosition`）。
判定用的是 `label` 节点而不是文本，是因为 `<select>` 的 textContent 是它的**选项**——用文本会把
"硕士学位"当成第三个标签，数量一对不上就白配。

**成因二：新增的那段经历"一条都没填上" → 块切分只认"签名完全一致"**

`buildBlocks` 原来只把"标签签名完全相同"的那组父容器当块。用户点了「添加教育经历」后，站点渲染的
第 2 段字段往往不完全一样（少一两个字段，或标签措辞变了："专业名称" → "所学专业"），两份签名对不上 →
整段退化成 **1 个 block** → 第 2 段的数据没有任何落点。
现在：多记录分类下，如果找不到"签名一致的一组"，就按父容器切块（每块至少 3 个字段，避免把两列布局的
字段行误当成两段经历）；`expandSections` 也改为"块数增加**或**字段数增加"都算点成功，
并按住每个分类的点按次数，防止块数不涨时多点出多余的一段。

**成因三（我们自己制造的失败）：日期控件是可编辑文本框时，先去开面板**

图里那份真实 DOM 说明：日期控件的值是 `type="text"` 输入框里的字符串（`value="2026-10-01"`），
外面套着 `listLInner / generic` 几层 div，点击会弹一个日历面板。原逻辑"先面板、后键入"，
而**面板失败后没关面板**，焦点还在面板上 → 键入被组件当场清空 → 判失败。
表面现象就是"弹窗拉起了，但开始/结束时间没填上"。

三层修法：
1. **能键入的纯文本框，先键入**（组件化日期控件 `DATE_CUSTOM/PICKER` 仍面板优先——它们只认自己面板的选中动作）；
2. **键入支持多种写法**：`2026-10-01` / `2026/10/01` / `2026.10.01` / `2026年10月1日` / `20261001` / 年月，
   谁"粘住"用谁。原来只试一种，一种被拒就整条链失败——这是"有的时间能填、有的不能"的主因；
3. **面板失败后先关面板再键入**，并在报告里写明是靠哪种格式填上的（`typing:ok(2026/10/01)`）。

**语言成绩 6.5 变成 6.50000**

原来写完文本**无条件 fire blur**，而站点的"补零/格式化"多半挂在 blur/change 上——是我们自己把 6.5 触成了
6.50000。现在：只发 `input`，值进不去才补 `change`；仍被补零就把原值盖回去且不再触发 blur；
站点坚持格式化时报「已按你的原值回写」，不再默默吞掉差异。

**学位词表**：补了 `学术型/专业型硕士`、`学术学位/专业学位` 等写法，避免"网站写学术型硕士、资料写硕士"时对不上。

**回归**：selftest 51、dom-test 91（新增 [13] 可编辑日期控件 6 条、[14] 两列字段行 5 条、[15] 不补零 1 条、[16] 新段签名不同 4 条）、beisen 164、panel-test 45。共 **351** 条全通过。反向验证四组（关掉位置配对 / 关掉切块兜底 / 恢复无条件 blur / 关掉键入优先）均按预期失败，[13] 反向时复现的正是 `panel → typing:value-rejected`。

### 2.0.20（多段经历自动扩充 / 弹窗拉起了但值没填上）

**① 资料库有 N 段经历、网页只渲染 1 段 → 自动点网页的「添加」再填**

新增 `src/repeat.js`，在"扫描完 → 绑定前"插一步：

1. 逐个区块比对「资料库里的有效记录数」和「网页上的块数」（空卡片不算一段，用户加了空行不该被当成经历）；
2. 只处理 `multiple` 且非自定义的分类，且**必须找到明确的添加按钮**才动手，找不到就老实只填第一段；
3. 点完 **必须重新扫描表单**（`buildFormModel()`）再重新绑定——点一下 DOM 就被框架重建了，手里那批 `field.el` 全是旧节点，继续用只会填到空气上；
4. 按钮识别有两道闸：文案带分类名（「添加教育经历」）最可信；只写「添加 / ＋」的必须位于**最后一块之后、且不在任何块内部**；「添加附件 / 上传照片 / 添加证书」直接按噪声排除。上限 8 次，防止死循环；
5. 点出来的如果是对话框（不是就地加一块）→ 自动点「取消」或发 Escape 收干净，不会把页面留在弹窗里。

报告顶部会多一行：`自动新增 2 个经历区块：教育经历：1 → 3 块（还差 2 段）`。扩充过程出异常只会降级成"只填第一段"，不会让整次填充变成 error。

**② 「可以看到拉起弹窗了，但开始/结束时间没有填充上」**

根因是**"弹窗开了"被当成了"值填上了"**：`drivePanel` 只要面板出现、点到了日格子就返回成功，至于组件有没有把值提交回外层输入框，没人校验。这一轮补了三处：

- **点之前先记住"已经存在的日历面板"，只认点开之后新冒出来的那个**。上一个字段的日历若只隐藏不销毁，会被"最深 / 数字最多"挑走 → 空转 → 现象正是"弹窗拉起了但没填上"；
- **面板还开着就补点一次「确定」，然后回读外层控件的真实值**再判成败。值没落上就不许报 `已填`；
- 失败报告里带出 **`panel-sel`（面板选择器）和 `panel-text`（面板内容，日网格的 1~31 已剔除）**，`尝试` 列写明走没走 `panel-confirm`。下次再失败，看这两项就知道卡在哪个日历、卡在哪一步。

顺带把 `pickYear` 认年份标题的正则放宽到「2026 / 2026年 / 2026年10月」三种写法——原来只认第一种，后两种会切不过年，后面月份日子全对不上。

**③ 所有筛选器日粒度（承接 2.0.19）**

`schema.js` 里已无 `'month'` 精度（`在校实践 / 获奖情况 / 发布时间` 全部 day），侧边栏一律日期选择器，写入时按「资料精度 ∧ 控件精度」自动降级。**这一版的改动是让"日粒度"这条链路真的能落地**——上面 ② 就是它落不了地的原因。

**回归**：selftest 51、dom-test 75（新增 [11] 多段扩充 11 条、[12] 弹窗未提交 8 条）、beisen 164、panel-test 45。共 335 条全通过。反向验证两次（`pickTarget` 直接返回 null / 去掉补点确定）均按预期失败，且反向失败时 `attempts` 恰好复现真机现象 `panel:ok → panel-open`。


### 2.0.19（三条反馈：自定义字段填不上 / 字段唯一性 / 所有时间字段与出生日期一致）

**① 自定义字段「无法适配、也无法被检测到」——三个成因都修了**

1. **只在所属分类里找 → 网页把字段放在别处就永远找不到。** 原来自定义字段只在"区块分类 == 字段所属分类"时参与匹配。现实是"微信号"经常被塞进「其他信息」，或者整块压根没被识别出分类（`categoryId = null`），这时候选池里根本没有它。现在**自定义字段全局参与匹配**（仍按名字去重、仍与内置别名去重）。反向验证：把作用域收回去，DOM 用例 [10] 三条全挂，`slot` 全是空。
2. **纯英文标签压根不算字段。** 标签识别的守卫是"必须含中文"，所以 `<label>GitHub</label>` 整个被丢掉 → 这个 input 连字段都不是（报告里是 `label-uncertain`）。现在**明确的 label 节点允许纯英文标签**（2-20 字符、字母开头、排除 submit/search/ok 这类按钮词）；兄弟文本那两条启发式通道仍然只认中文，避免把按钮文案当字段名。
3. **名字对不上时它悄悄消失了。** 报告里一条都不出现，看起来就像"没检测到"。现在填充结束后会做一遍专项检查：**资料库里有、这次却没匹配上**的自定义字段补一条 `已跳过 / custom-no-match`，并把字段名带在"字段"列里。只对"这次页面上真的出现过的分类"报，不会刷屏。

**② 同一分类下的字段唯一性监测**

输入时就点出来（不重渲染，改字即时刷新）：
- 字段名为空 → 「没填字段名，这条不会被填充」
- 与**任何内置字段的标签/别名**重名 → 「和内置字段重名：内置的优先，这条不会被填进去」
- 与**同一分类下另一条自定义字段**重名 → 「同一分类下有同名字段，只有第一条生效」

重名行会标红并给出原因，而不是默默丢掉。判定规则和 binder 里的一致（撞名 = 内侧优先，自定义那条被丢弃），所以"提示消失"就等于"这条会被填"。老的「自定义字段」分类里的"字段名称"也纳入同一套监测。

**③ 所有"事件时间"字段都按出生日期的方式处理**

`到岗时间`、`在校职务/在校实践起止`、`获奖时间`、`发布时间` 全部从"年月"改成**日粒度**：侧边栏一律是日期选择器（不再有「年月」小标），填充时同样按「资料精度 ∧ 控件精度」自动降级到年月。**从此没有"月粒度字段"这个概念**，逻辑测试里加了一条硬断言：所有 `kind === 'date'` 的字段 `precision` 必须是 `day`。

**顺手**：无。这轮没碰下拉/弹层那块。

**回归**：selftest 51、dom-test 56（新增 [10] 跨区块 + 英文标签 + `custom-no-match`）、beisen 164、panel-test 45（新增 [9] 唯一性监测、[10] 老分类唯一性；[6] 改为"所有日期字段都是日粒度"）。共 316 条全通过。反向验证三次（收回自定义字段作用域 / 关掉英文标签通道 / 关掉 `custom-no-match` 诊断）均按预期失败。

### 2.0.18（需求轮：日粒度日期 / 最高学历 / 分类级自定义字段）

三件事，外加一个顺手修掉的隐藏 bug。

**① 教育经历 / 实习经历的时间改成日粒度，但要能落到只看年月的网页**

- 侧边栏里 `edu.start` / `edu.end` / `exp.start` / `exp.end` 现在是 `type="date"`（能填到日）；`到岗时间`、`获奖时间`、`在校职务/实践` 的时间仍只到年月，标签上仍挂「年月」。
- 填充时**有效精度 = min(资料值精度, 控件能力)**，不是无脑按字段声明写：
  - 资料 `2021-08-15` + `type="month"` 控件 → 写 `2021-08`，校验只比年月，报告里标「（网页只到年月，已按年月写入）」；
  - 日历面板只有年月格子（没有日格子）→ 走 `panel-month` 直接点月份，不再报 `no-day-grid` 然后回滚；
  - 回读里没有"日"一律判成功（`month-ok`），不再算 `date-verify-failed`。
- **v1 老数据（`2020-09`）不会被擅自补成 `2020-09-01`**：侧边栏显示时补 01 号并标「仅年月」，资料库里仍是 `YYYY-MM`，写网页时按年月精度走。这是刻意选择——补一个"日"等于替你编数据。

**② 个人信息新增「最高学历」**（`personal.highestDegree`，复用 `degreeLevel` 词表）

它和 `edu.degreeLevel` 的"包含"关系天然会打架（最高学历 ⊃ 学历）。为此 `binder` 新增**反别名**（`deny`）：`personal.highestDegree` 明确拒绝「学历 / 学位 / 学历层次 / 培养层次」这些标签。效果：
- 个人信息区的「学历」照旧落到 `edu.degreeLevel`（历史行为不变）；
- 写着「最高学历」的标签落到 `personal.highestDegree`；
- 教育经历区里写「最高学历」仍然落到那条记录的 `edu.degreeLevel`（靠包含打分）。

**③ 每个分类下都能加自定义字段**

- 数据挂在记录上：`__custom: [{ name, value }]`。侧边栏每张记录卡片底部都有「自定义字段 ＋ 添加」，一行 = 字段名 + 内容 + 删除。
- 填充时按**你填的字段名**去匹配网页标签，槽名 `custom:<分类>:<字段名>`；与内置字段别名撞名的条目会被丢掉（否则会让"精确命中多个槽"变成歧义，反而把能填的字段变成不填）。
- 老的「自定义字段」分类不再是死角落：它的记录（字段名称 / 字段内容）现在**全局生效**，槽名 `custom:global:<字段名>`；分类内同名优先。

  <span class="phoenix-select__calcEle">…</span>                        ← 真值写这里
  <div class="phoenix-select__placeholder phoenix-select__placeholder--active">畲族</div>  ← 旧值不清
  <ul class="phoenix-select__content">
    <li class="phoenix-select__inputWrapper phoenix-select__inputWrapper--emptyMultiValue">
      <input class="phoenix-select__input …unText" value="畲族">        ← 同时是搜索框
    </li>
    <span class="phoenix-select__tipWrapper phoenix-select__tipWrapper--active">
      <span class="phoenix-select__tipEle">畲族</span>                   ← 第三处显示
    </span>
  </ul>
</div>
<div class="phoenix-unmodeled-layer block">
  <div class="phoenix-unmodeled-layer__inner"> … 浮层 portal 容器 …
```

**四个根因**

1. **最致命的一条：点选失败后不会换路子**。`writeSelectCustom` 在"点选 + 确定 + 回读不符"之后**只做 `repickOption`（再点一次）**，
   然后直接判 `failed`。而这个组件的问题是"点得中、确定也点了，值就是不提交"——再点一百次也没用，
   必须换成键盘提交。键盘路径（`commitByInput`）只在"列表里根本匹配不上"时才会被调用，**从来没被触发过**。
2. **`phoenix-unmodeled-layer` 不在面板选择器里**：籍贯的 `panel-not-open` 就是这个——浮层明明挂在
   `phoenix-unmodeled-layer` 上，`PANEL_SEL` 一个都匹配不到。
3. **`repickOption` 重开面板前没先关面板**：上一轮弹层还开着时再点触发器等于"收起"，
   `openPanel` 会一直等一个永远不会出现的面板 —— 真机 `repick:fail` 就是这么来的。
4. **`clickConfirm` 匹配太窄**：`children.length <= 1` 且用 `shortText(el, 4)` 比（"确 定"带空格就匹配不上），
   按钮里套个图标就点不到。

**修复**

| 位置 | 改动 |
|---|---|
| `writeSelectCustom` | 回读不符时**先走键盘路径**（`input-keys`），再 `repickOption`，最后才判 failed；`attempts` 记录完整链路 |
| `commitByInput` | 提交方式四级递进，每级都回读：① 点项+确定 → ② 裸回车 → ③ ↓+回车 → ④ ↓↓+回车 |
| `PANEL_SEL` | 新增 `[class*="popper"]`、`[class*="unmodeled-layer"]:not([class*="__"])` |
| `repickOption` | 重开前先 `closePanel()` |
| `clickConfirm` | 文本去空白后比，`children.length <= 2`，排除 disabled，最内层优先 |
| `readTriggerText` | 值节点补 `[class*="tipEle"]`（截图第三处） |
| `clickEl` | 先派发 `mouseover` / `mousemove`（部分自绘列表项要 hover 之后才可点） |
| 点选后等待 | 140ms → 260ms（多选组件点完才渲染「已选 1/1 + 确定」这一段） |

**验证**：beisen-test 101 → 109（新增第 [17] 组：完全按截图复刻——三处值显示、点得中、确定点了没反应、裸回车也没反应，只有 ↓+Enter 才提交）。四套合计 37/35/109/14 = 195。

反向验证：把"回读不符时先走键盘"这段撤掉，第 [17] 组立刻复现你这次的报告 ——
`failed` + `readback-mismatch` + `readback: "畲族"` + `attempts: [..., "repick:still-mismatch"]`。

### 2.0.11（真机第十轮：侧边栏取消所有"选择"交互 + 回读被 placeholder 旧值污染）

**真机反馈**（两件事）：

1. 「插件中不做选择了，全部改成让用户自己填写字段」；
2. 「筛选器弹窗中完成了对目标字段的筛选，但还是没有完成选择」——截图红框标了
   `div.phoenix-select__placeholder--large`（值"畲族"）和 `input.phoenix-select__input--unText[value="畲族"]`。
   诊断：`available: []`、`panelText: "搜索结果1个 傣族 已选1/1 清空已选 畲族 取消 确定"`、`attempts: ["input-enter:readback-mismatch"]`。

**改动一：侧边栏不做选择（产品决策）**

枚举字段的 `▾` 下拉整套删掉 —— 输入框右侧按钮、`role=listbox` 菜单、`enum-item/enum-hint` 样式、全局"点空白收起"监听，全部移除。
所有字段（含性别 / 政治面貌 / 民族）现在都是**纯文本输入框**，由用户自己填写。

理由：插件里选得再准，页面上仍是另一套交互（自绘弹层 + 确定按钮），两边语义对不齐，反而制造"我以为选对了"的误判。
枚举词表**保留**在 `schema.js` / `resolver.js`，只在填充时做同义词归一（用户填"傣"，页面上仍能对上"傣族"），不影响输入时不改写用户原话。

**改动二：三个页面侧根因**

1. **选项收集漏掉"带图标/角标的网格项"**：`candidateNodes` 原来只收 `children.length === 0` 的叶子节点。
   北森网格项形如 `<div class="gcell">傣族<i class="dot"></i></div>` —— 有子元素所以不是叶子，
   `<i>` 里没文字也进不了候选，整项被漏掉。现在加第三条通道：**`TreeWalker` 遍历所有文本节点，取其父元素**。
   元素类型、层级、可见性判定都可能骗人，但"这段文字在不在 DOM 里"不会骗人。
2. **回读被 placeholder 的旧值污染**：Phoenix 把新值写进 `phoenix-select__calcEle`，但 `phoenix-select__placeholder` 里的旧值**不清**。
   旧 `readTriggerText` 把整块文本拼起来得到「傣族 畲族」，永远对不上目标。现在先按 `calcEle / placeholder / selection / value`
   找"值显示节点"，取**最短的那一个**（最具体），不再拼整块。
3. **搜索后只剩 1 个结果就把面板判成"没有选项"**：`growToOptions` 阈值从 `>= 2` 降到 `>= 1`。
   搜"傣"只出"傣族"一项时，`>= 2` 会让它继续往上爬 4 层，最后把整个表单当成面板 —— 比选不中更糟。
   右栏「已选 1/1 + 已选值」那种假阳性已由 `JUNK_RE` 与 `insideSelectedPane` 挡掉。

**新增诊断 `probe`**：失败时报告里多三个字段，一次定位"为什么收不到选项"——
- `panelSel`：面板实际定位到的节点（`tag.class`）
- `probe.nodes`：候选节点总数；`invisible / hasTextChild / inSelected / tooLong / junk / kept`：各阶段淘汰计数
- `probe.samples`：被淘汰的文本样本（各前 6 条）

**验证**：beisen-test 96 → 101（新增第 [16] 组：calcEle 与 placeholder 同时有字，断言回读是"傣族"而非"傣族 畲族"）；
panel-test 19 → 14（整组重写为"没有任何选择控件"：无 `enum-caret` / `enum-menu` / `[role=listbox]` / `[role=option]` / `datalist`，且手填值原样入库）。
四套合计 37/35/101/14 = 187。

反向验证：把 `readTriggerText` 退回"整块 innerText 拼接"，第 [16] 组立刻读到 `"傣族 畲族"` —— 正是真机上永远匹配不上的那个值。

### 2.0.10（真机第九轮：看得见却点不到 —— 选项收集被一个计数 li 掐断）

**真机反馈**：「可以在筛选器的搜索结果看到目标的民族，但是无法完成选择」——搜索框已经能把「傣族」过滤出来，页面上肉眼可见，但程序就是选不中。诊断：
`available: ["搜索结果1个", "畲族"]`、`panelText: "搜索结果1个 傣族 已选1/1 清空已选 畲族 取消 确定"`、`attempts: ["input-enter:readback-mismatch"]`。

**根因（一处，很隐蔽）**：`collectPanelOptions` 原来是「**二选一**」策略 ——
先按 `OPTION_SEL`（`[role=option], li, [class*=option]`）找；只要命中**任何一个**，就认为「已经找到选项列表」，**不再**退到"短文本叶子"兜底。
而双栏选择器里恰好有一个 `<li>搜索结果1个</li>`（计数文案，不是选项），它命中了 `li` → 兜底被掐断 → 真正的民族项是 `div` 网格 → 一个都没收进来。
`available` 里那两条就是"计数文案 + 右栏已选值"，跟真机诊断一字不差。

**修复**：
1. **`candidateNodes()` 改为合并**：`OPTION_SEL` 命中的节点 ∪ 所有短文本叶子节点（`div/span/li/a/p/dd/dt` 且无子元素），去重后一起进筛选管线。不再有"命中即停止兜底"的分支。
2. **`insideSelectedPane()`**：右栏「已选 N/M」里的 chip 是"待确认的选择"，不算可选项（往上找 ≤3 层，命中 `已选 x/y` 短文本即排除）。
3. **`JUNK_RE` 补 `搜索结果.*` 与 `共\s*\d+\s*[个条项]?`**：这类计数文案一律不当选项。

**验证**：beisen-test 90 → 96（新增第 [15] 组：弹层里同时有 `<li>搜索结果1个</li>` 和 div 网格民族项，断言从网格里点中"傣族"→ 点"确定" → 页面与输入框都变成傣族）。

反向验证：把 `candidateNodes` 退回"命中 `OPTION_SEL` 就不兜底"，第 [15] 组立刻复现你这次的诊断 —— `no-options` + `input-enter:readback-mismatch`，页面仍是畲族。

### 2.0.9（真机第八轮：弹层搜索框 + 枚举改成下拉）

**真机反馈**：「我切换民族就无法填写成功了」——页面当前是汉族，改成傣族填不上。诊断：
`available: ["1/", "汉族"]`、`panelText: "已选1/1 清空已选 汉族"`、`attempts: ["input-enter:readback-mismatch"]`。

**三个根因**：
1. **面板仍然只定位到右栏**：「已选1/1」+ 已选中的「汉族」凑够 2 条，让 `growToOptions` 的 `>= 2` 阈值通过了，于是左栏网格根本没被收进来 —— `available` 里那两个"选项"就是右栏的计数和已选值。
2. **`1/` 没被当成垃圾文本**：`JUNK_RE` 里有 `\d+\/\d+` 却没有 `\d+\/`。
3. **搜索框在弹层顶部，够不着**：真正能过滤左栏网格的搜索框不在当前面板里，`tryTypeFilter` 于是退而把值敲进**触发器**的输入框（那只是显示当前值的地方），既没过滤出傣族，还污染了触发器显示。

1. **`popupRootOf()`**：从面板往上爬到"含一个非触发器的可输入框"的那一层 = 弹层根。爬到包含触发器的祖先（说明已进表单区）立即放弃，所以不会越界。
2. **`JUNK_RE` 补 `[\d/]+`**：`1/`、`1/1`、`0/1` 一律不当选项。
3. **`commitByInput` 失败后还原输入框原值**：不再把触发器里"当前已选的值"擦掉（那是显示区，不是搜索框）。

**侧边栏 UI（按你的要求改）**：枚举字段从"全部铺开"改成**输入框 + 下拉**——
- 输入框右侧一个 `▾` 按钮，**默认收起**，点开才看到全部可选值（民族 56 项在 208px 高的列表里滚动）；
- 当前值在下拉里高亮；点选项即写入并自动收起；同时只开一个，点空白处收起；
- 仍然保留**手输自由文本**（词表里没有的值，比如「无党派人士」，照原样保存，不会被吞掉）。

**验证**：beisen-test 85 → 90（新增第 [14] 组：双栏 + 顶部搜索框，汉族切傣族）；panel-test 16 → 19（下拉形式：默认收起 / 点开 / 选项写入 / 同时只开一个 / 自由文本保留）。

反向验证：把 `popupRootOf` 退回"不往上找"，第 [14] 组立刻复现你这次的诊断（`option-no-match` + `input-enter:readback-mismatch`，页面仍是汉族）。

### 2.0.8（真机第七轮：双栏选择器 + 可编辑下拉直填）

**真机反馈**：民族仍填不上。诊断给出了决定性证据：
`reason: no-options`、`available: []`、`panelText: "已选0/1 清空已选 请在左侧选择内容"`；截图里弹层是**左栏民族网格 + 右栏「已选 0/1」+ 底部「取消 / 确定」**的双栏选择器。

**三个根因**：
1. **面板定位停在了右栏**：`panelAround` / 类名选择器把右栏（只有「已选0/1」这类提示文字）当成了面板 → 选项一个都收不到 → `no-options`。
2. **「确定」在面板外面**：双栏选择器把确认按钮放在弹层页脚，点是点了左栏选项，但不点确定值不提交；旧代码只在面板内部找确定，永远找不到。
3. **「已选0/1」被当成选项**：`JUNK_RE` 没覆盖这种计数文本，进一步把面板判定带偏。

**修复**：
1. **`growToOptions()`**：选中的容器若一个选项都收不到，就往上爬最多 4 层，直到找到真正含选项的容器（到 body/html 为止，遇日历即停）。
2. **`clickConfirm()`**：在面板及其最多 2 层祖先里找「确定/确认/完成」，覆盖"按钮在页脚"的双栏选择器。
3. **`JUNK_RE` 扩充**：新增 `已选*`、`\d+\/\d+`、`全部`、`在选择框中选择内容`。
4. **新增 `commitByInput()`（按你说的"日期方式"）**：可编辑下拉（`phoenix-select--editable`）直接把值写进它的 input（原型 setter + 冒泡 `input`）→ 列表若过滤出目标项就点它 → 否则回车提交 → **回读校验**；失败才清空过滤词跳过。报告中 via 为 `input+click` 或 `input-enter`。
5. **回读去重**：显示区常把同一个值渲染多份（真机回读是 `共青团员共青团员共青团员`），`collapseRepeat()` 折叠成 `共青团员`。

**顺带**：`container` 落在 `body/html` 上的控件（真机的游离 textarea）不再算作表单字段，少一条无意义的 `label-uncertain`。

**验证**：beisen-test 79 → 85（新增第 [12] 组：双栏选择器 + 可编辑输入框直填）；dom-test 33 → 35（新增第 [6] 组：body 下游离控件）。四套合计 173 条。

反向验证：把 `clickConfirm` 退回"只在面板内找"，第 [12] 组立刻变成 `readback-mismatch`、确定按钮点击次数 0 —— 与真机"能弹窗但填不上"一致。

### 2.0.7（真机第六轮：修"填错值"+ 侧边栏展示枚举全量）

**真机反馈**：民族能自动填上了，但**填成了「黎族」，而资料库里是「汉族」**。填错比跳过严重得多——这一版把它按"绝不写错值"的标准修掉。

**根因**：虚拟列表**复用 DOM 节点**（只改 `textContent`，不卸载重建）。手里那个节点 `isConnected` 一直是 `true`，所以旧代码不会去重新定位；而 `scrollIntoView` 本身会触发滚动 → 窗口整体位移一格 → 手里这个节点此刻显示的是**相邻的另一项**，点下去就选了「黎族」。
旧代码对这种情况只在"回读不一致"时报 `readback-mismatch`（所以诊断里能看到失败，但页面上的错值已经留下了）。

**修复**：
1. **点前重取 + 点前核字**（`pickFreshOption`）：滚进视口 → 等 160ms → **按标签重新取节点**（不沿用旧节点）→ 再核一次"这个节点现在显示的必须就是目标项"，否则重定位，核不上就不点（`option-detached` 跳过）。
2. **`relocateOption` 从顶部重新找**：先 `scrollTop = 0` 再逐屏向下，避免目标项在当前位置"上方"永远找不到。
3. **回读改为"显示节点优先"**：自绘下拉的 `input` 常常就是搜索框，里面留着我们键入的过滤词（"汉族"）。以前它优先被当成回读值，正好掩盖了"其实选成了黎族"。现在先克隆容器、剔除 label/input 读显示文本，读不到才退回 `input.value`。
4. **点歪后自动补救一次**（`repickOption`）：回读不一致时重开面板、按标签重新定位再点一次；仍不一致才报 `readback-mismatch`（失败），并把两次回读都写进报告。
5. **`harvestOptions` 收尾等待 80 → 160ms**：给异步重渲染留出时间，否则收割完立刻定位会读到上一帧的窗口。

**顺带修一个数据缺陷**：`ETHNIC_NAMES` 只有 55 项，**缺「仡佬族」**——该民族在网页上永远填不上。已补齐到 56 项。

**侧边栏 UI**：
- 枚举字段下方平铺**全部可选值**（可点选），当前值高亮：性别 → 男/女/保密；政治面貌 6 项；证件类型、学历、学位同理。
- 长列表（>16 项，如民族 56 项）默认收起，**字段一旦有内容就自动展开**，也可手动开合；展开区最高 126px 可滚动。
- 选项 >6 项的字段占整行；移除了原来的 `datalist`（它只按输入内容过滤建议，正是"看不到全部值"的原因）。

**验证**：beisen-test 78 → 79（新增"scrollIntoView 引发的窗口位移真的发生过"作为复现条件断言）；新增 `scripts/panel-test.mjs` 16 条（枚举平铺 / 高亮 / 点选 / 长短列表开合）。四套合计 165 条。

反向验证做了：把"点前重取"退化成旧逻辑后，同一用例会填成「傣族」并报 `readback-mismatch`——与真机现象一致，说明这个回归测试不是空转。

### 2.0.6（真机第五轮：民族这一类虚拟滚动筛选器 + 月粒度日期）

**真机反馈**：出生日期已能填上，民族仍旧 `option-no-match`。并明确了一条约束：民族代表的是一整类筛选器，不能只修这一个字段。

**根因（两个，都不是"民族"特有的）**：

1. **虚拟滚动列表**：56 个民族的列表只渲染可视区那 8~10 个 DOM 节点，`汉族` 之后的项根本不在 DOM 里。点击前后做差集、按类名收集选项，都只能看见首屏 8 项 → 目标项永远收集不到。
2. **面板会被认成内层 list**：`findPanelBySelector` 用 `innerText` 判空，jsdom / 未渲染 portal 里 `innerText` 为空 → 这条"按类名找面板"的便宜路径静默失效，退回点击差集去猜容器，猜到的是内层 `.list`；而滚动容器恰好是它自己、不在自己的子树里 → 收割时找不到滚动容器。

**修复**：

1. **`harvestOptions()`**：面板内可滚动容器逐屏滚一遍，边滚边收，只读不点（不会误选）。滚动容器识别抽成 `scrollerCandidates(root)`，**根节点本身也参与判定**（差集法常把内层 list 当成面板）。

### 2.0.3（真机 66 字段填 0 个 → 修 phoenix-select）

**症状**：第二次真机诊断 `total:66 / filled:0 / empty:12 / no-record:16 / label-uncertain:38`，38 个 `label-uncertain` 的 `container` 全是 `div.phoenix-unmodeled-layer__inner`。

**关键发现**：侧栏里有值的 5 个字段（性别 / 出生日期 / 证件类型 / 政治面貌 / 民族）在报告里**一个都没出现**——它们全是北森 `phoenix-select` 自绘下拉，标签取不到 → 连绑定都没进；而绑上的 12 个字段是因为资料库里本来就是空的（`empty`）。所以"什么都没填"= 有值的字段全在取不到标签的那一类里。

**根因**：
1. `findContainer` 只向上爬 6 层，而 `phoenix-select` 的内部结构是 `input < .phoenix-unmodeled-layer__inner < .phoenix-unmodeled-layer < .phoenix-select < .form-item__control`，爬到第 6 层还没到带标签的 `.form-item` → 标签全空；
2. 自绘组件的输入框在 DOM 里就是个普通 `<input>`，`detectControlKind` 判成 `TEXT` → 就算绑上也会往里写值，网页不认（等于没填）；
3. 自绘单选按"直接父级相同"聚合，`phoenix-radio > .phoenix-radio__circle` 这种两层结构的叶子各自父级不同 → 性别整个漏掉；
4. 下拉面板只按类名（dropdown/panel/option）找，北森真实面板类名不可预知 → `panel-not-open`。

**修复**：
1. **`formItemAncestor()`**：按 BEM 类名（`form-item` / `ant-form-item` / `el-form-item` / `moka-form-item` …）直接 `closest` 到"一个字段一行"的根节点，不再靠层数碰运气；`findContainer` 优先用它，兜底爬到 10 层。
2. **`refineKindByComponent()`**：按祖先类名判定控件类型——`cascader` → CASCADER（跳过）、`date-picker|datetime|calendar` → DATE_CUSTOM、`select` → SELECT_CUSTOM。
3. **自绘单选重做**：改为"向上找第一个同时满足 ≥2 个选项叶子 + 能取到标签 + 不含原生控件"的祖先，两层结构也能聚合。
4. **下拉面板两条路**：先按类名找（便宜），失败则用"点击后新增的短文本节点反推共同容器"（不依赖任何类名）；选项节点没有 option 类名时退化为"短文本叶子"。打开面板依次尝试 输入框 → 整块容器 → 组件内部 selection/trigger。
5. **诊断**：`label-uncertain` 与所有跳过/失败的字段都带 `path`（祖先链，如 `<input> < div.phoenix-unmodeled-layer__inner < div.phoenix-unmodeled-layer < div.phoenix-select`），`panel-not-open` 额外带 `hints`（当前可见的疑似面板节点）。

**验证**：`scripts/beisen-test.mjs` 新增第 7 组用例，按真机类名复刻 `form-item / form-item__label / phoenix-select / phoenix-unmodeled-layer`，断言：标签能取到、容器是 `.form-item`、`phoenix-select` 判为 SELECT_CUSTOM、能绑到 `personal.gender`、点击后（面板类名不带任何关键词）仍能识别并选中。该组 10 条断言全过，套件 39 → 49。

**仍未解决**：区块标题（`识别区块` 那行仍可能是 `(未命名)×1块/68字段`）。它不影响单条记录的填值，只影响"同页多段经历"的块对齐——下一轮再按 `path` 校准。

### 2.0.2（修复"69 个字段填 0 个"）

**症状**：北森真机诊断里 `filled: 0 / skipped: 68`，几乎全是 `label-uncertain` 且 `label`、`parts` 都是空；`sections` 里显示的全是字段名（「在校职务类别」「在校职务名称」…）。

**根因（四个叠加）**：
1. **标签取不到**：`findContainer` 之前会停在"只包住 `<input>` 的那层 div"，而北森把标签放在它的父级 `.bx-form-item-title` 里 → `labelTextsOf` 得到空数组 → 标签全空。
2. **每行都成了区块**：`sectionOf` 不要求"至少 2 个字段"，于是每个字段行自己被当成一个区块，标题就是字段自己的名字。
3. **纯 div 单选看不见**：北森 `bx-radio` 没有 `role="radio"`，性别这种自绘单选组完全没被发现。
4. **区块标题没有"不是字段名"的守卫**：`matchSection` 允许长文本，字段名冒充区块名成功。

**本轮修复**：
1. `findContainer` 改成「标签优先」：向上最多 6 层，找到**第一个能取到标签文本**的最小容器；标签文本覆盖 label 元素 / `class*=label|title|caption` / 直接子节点 / 前一个兄弟 四条路径。
2. `sectionOf` 要求该祖先 `countFields >= 2`；`sectionTitleOf` 支持 `legend/h1-h5`、`class*=title|header|head|caption|legend` 的直接子节点、以及节点自身文本；标题长度上限 12 字。
3. `matchSection` 分三级：**精确等于区块名**（最高优先级）→ 字段名守卫（`FIELD_LABEL_SET`）→ 包含式匹配。顺带修掉"在校职务"既是区块名又是字段别名时被误杀的问题。
4. 词典里没有的标题（如「简历附件」）也接受为**区块边界**（`categoryId` 留空，交给 `inferCategory`），避免所有字段塌进 `(未命名)` 一个大区块、把重复块分组也带坏。
5. 自绘单选组聚合：同一父容器下 ≥2 个 radio 叶子 → 合成一个逻辑字段，容器取「**同时满足"包住全部选项"和"能取到标签"**」的最小祖先（只按其中一个条件都会取错：前者停在无标签的 `.bx-radio-group`，后者停在单个「男」上）。
6. **原生单选/复选按 `name` 合并**：之前 `<label class="radio"><input type=radio>男</label>` ×2 会被切成两个字段，每个只看到自己那一个选项 → 永远 `option-no-match`。现在合并成一个字段，容器扩到能包住全部选项的那层。
7. 事件派发改用 `fire()`：从元素所属 realm（`ownerDocument.defaultView`）取 `Event` / `MouseEvent` / `KeyboardEvent` 构造器。这修掉了跨 realm（iframe、jsdom、某些容器内嵌页）下 `dispatchEvent` 抛 `parameter 1 is not of type 'Event'` 导致整字段填入失败的问题。
8. 标签长文本兜底：`"手机 请输入11位手机号"` 这类带提示语的标签，取第一个短片段 `"手机"`。
9. 诊断增强：每条结果新增 `container`（如 `<div.bx-form-item>`）、`label-uncertain` 额外带 `el` 与 `parts`；报告新增**「原因分布」**一行（谁在失败、失败多少次），一眼看出是"标签取不到"还是"选项匹配不上"。

**验证**：新增 `scripts/beisen-test.mjs`（复刻北森 `bx-card / bx-form-item / bx-form-item-title / bx-radio` 结构）39 条断言全过——8 个字段全部取到标签、区块标题是「个人信息/在校职务」而不是字段名、性别走单选组点中、政治面貌无面板时跳过且不留脏值。

## 4. 测试怎么看结果

点「填写当前网页」后，侧边栏顶部会出现**填充报告**，分为：

| 状态 | 含义 |
|---|---|
| 已填 | 写入并回读一致 |
| 低置信 | 写进去了，但回读口径不完整（如自绘下拉读不到明确选中文本），**请人工扫一眼** |
| 已跳过 | 按你的要求：匹配不上就跳过。说明列会写清原因（无匹配 / 歧义 / 面板没打开 / 标签认不出） |
| 失败 | 写入抛错或回读不一致（此时不会留脏值） |

**"说明"列会给出网页真实选项**，例如：
`选项里没有匹配值（网页选项：博士 / 硕士 / 本科 / 大专）`
看到这个就说明：资料库里那个值在这页的选项集里不存在，改资料值或告诉我加映射。

右上角「复制诊断」会把整份报告 JSON 复制到剪贴板，**测试时请优先用这个反馈**，比截图有用得多。

### 4.1 2.0.2 版报告新增的两个信号（先看这两行）

- **「识别区块：个人信息×1块/5字段　教育经历×1块/4字段 …」**
  - 出现 `(未命名)` → 那块标题没被认出（词典没有 + 兄弟节点也没标题），字段仍会按字段名绑定，但区块边界可能不准。
  - 出现**字段名当区块名**（如 `在校职务类别×1块`）→ 说明扫描仍在把单行当区块，直接把这段文字发我即可定位。
  - 区块内**字段数**能立刻暴露"漏扫"：页面上明明 6 个框，这里只有 2 个，就是控件识别漏了。
- **「原因分布：网页标签无法确定对应字段×12；下拉/日历面板未打开×4 …」**
  - 全是「标签无法确定」→ 问题在扫描层（标签取值），把对应字段的 `container` / `parts` 发我。
  - 全是「面板未打开」→ 问题在交互层（日期/下拉点击后没弹层），我按站点补探测。
  - 全是「选项里没有匹配值」→ 问题在数据层（资料值与网页选项集不重合），改资料值或加映射，不是 bug。

## 5. 这一版到底改了什么（对照 v1）

| 问题 | v1 行为 | v2 行为 |
|---|---|---|
| 教育/实习都有「开始时间」 | 值池冲突 → `bestMatch` 返回 null → **一次都不填** | 语义槽 `edu.start` / `exp.start` + 区块作用域 → 分别填对 |
| 网页 2 个教育块，资料 2 条记录 | 无法对齐，可能全填第一条 | 按学校名/单位名强键配对；顺序错乱也能对 |
| 资料库里「姓名」与「家庭成员姓名」重复 | 姓名也会一起失效 | 分类内匹配优先，`personal.name` / `family.name` 各归各位 |
| 学历放在「基本信息」区块 | 无对应 key，不填 | 全局唯一时允许跨区块回退到 `edu.degreeLevel` |
| 教育起止时间（年月粒度） | 校验强制 y-m-d → 填对也判失败并回滚 | 精度模型：`edu.start` 只校验到年月 |
| 日期选不上 | 面板定位靠 Phoenix 类名硬编码 | 能力探测（原生 select / 年网格 / 月网格 / 日格 / 翻页），失败逐级降级 |
| 选项匹配 | 10 条硬编码别名 + 字符重叠 | canonical 枚举字典（19 类）+ 双向匹配 + 反向回读 |
| 匹配不上时 | 可能硬写一个近似值 | **自动跳过**，不点、不写、不改网页原值 |
| 失败后 | 可能留下脏值 | 日期链路失败回滚原值；跳过前清掉输入过的过滤词 |
| 结果可见性 | 只有 console.log | 结构化报告表格 + 可复制诊断 |

## 6. 已知限制（务必先看，避免误判为 bug）

1. **日期选择器尚未针对北森/Moka 校准**。我实现的是一套通用能力探测，代码里保留了 Phoenix 的类名特征。如果北森用的是很特殊的日历结构，可能全部落到「已跳过（面板没打开）」。这是**预期内的失败方式**——跳过比填错好，但需要你把报告发我，我按真实结构补。
2. **Moka 是分步表单**：只填当前可见步骤，看不到的字段不会被填。切到下一步后需要再点一次「填写当前网页」。
3. **多选组（checkbox）暂不支持**，会产生「已跳过（多选组暂不支持）」。
4. **籍贯 / 户籍省市区级联**尚未实现（`CASCADER` 适配器未做），多级下拉会被跳过或只填第一级。
5. **「工作经历」按「实习经历」分类处理**（v1 就是这么分的），所以如果页面同时有实习和工作两块，会共用同一个记录列表。
6. **学校的搜索型下拉**：会先键入再匹配选项；如果该站点下拉不支持键入过滤，只能匹配已渲染出的选项。
7. **虚拟滚动列表靠"滚动收割"兜底，有上限**：面板内最多识别 3 个滚动容器、每个最多滚 10 屏。超过约 80 项、必须滚很远才能看到的选项可能仍收不全（报告里 `available` 只给前 20 项，够判断）。
8. **需要"点页码翻页"而不是滚动的选项列表**（底部有 1/2/3 页码）当前不会点页码，会判 `option-no-match`。
9. **月粒度日期是"先试 YYYY-MM，被拒再补 01 号"**：如果某站点日历对补齐值也校验失败（例如禁选未来月份），仍会跳过，不会写脏值。
10. **自绘下拉选错后无法回滚**：点歪了会自动重挑一次，两次都不对时报告里是「失败 + 回读：xxx」。但已经把错值写进网页组件的那一次**没法清掉**（自绘组件的值只能通过它自己的交互改），需要你手工改一下——报告里会写明"应为哪一个"。
11. **照片上传**要求网页是原生 `<input type=file>`；如果是自绘上传按钮，会跳过。
12. **已勾选的单选/下拉不会被重填**（当前不判断幂等），重复点击「填写当前网页」可能覆盖你手工改过的值——测试时注意。
13. **"区块"是启发式判定**：要求该祖先至少含 2 个字段、且能取到 ≤12 字标题。如果某站把整页所有字段塞进一个容器、只用一个总标题，那么它会被认成 1 个区块——字段仍能按各自标签绑定，但"重复块"对齐会退化为按顺序。
14. **选项收集是"文本启发式"**：面板里凡是「短文本、可见、不像计数/按钮文案」的节点都会被当成候选选项，v2.0.11 起还包括**所有短文本节点的父元素**。如果某站的下拉里混入了长得像民族名的说明文字，可能被判成选项（概率低）。判定依据是 v2.0.10/2.0.11 的教训：宁可多收再靠 `JUNK_RE` 过滤，也不能因为"找到一个像列表的元素"就停止往下找——那会导致"肉眼看得见却点不到"。
15. **侧边栏不做选择，值靠用户手填**（v2.0.11 起的明确产品决策）：插件里没有下拉/单选/列表，全部是文本输入框。填"傣"这种简写时，页面填充仍能通过词表对上"傣族"；但**填了词表里没有的值就会原样搬到页面上**，由网页自身校验。
16. **失败报告新增 `probe` 字段**：`panelSel` + 各阶段淘汰计数（`invisible / hasTextChild / inSelected / tooLong / junk / kept`）。如果某次仍然选不上，把这个字段发我 —— 它直接说明"选项是在哪一步被丢掉的"，不用再靠现象猜。
17. **民族 / 籍贯这类弹层走"点 svg 图标"路线**（v2.0.16 起）：这类弹层点文字是**空的**（叶子节点 `handleLabelClick` 直接 return 或只展开下一级），只有选项左侧那个 14×14 的 `svg.RadioUnchecked / RadioChecked`（地区弹层是 `svg.area-icon-RadioUnchecked`）才触发勾选。两套类名现在都认。点完会回读右栏「已选」chip 列表确认；如果确认不到，**不会去点确定**（`saveSelectData([])` 会把字段清空）。所以这种情况报告是 `failed / itemClick: icon-nochange`，页面上不会出现「请选择必填」。
18. **`itemClick` 字段**：只在弹层这类能给局部反馈的组件上出现，取值 `icon / icon-retry / icon-already / icon-nochange / icon-disabled / text`。`text` 表示走的是老路（点文字 + 补点原生控件），成败只能靠回读判 —— **看到 `text` 就说明没认出这个组件的图标**，把 `itemClick` + `panelSel` 一起发我即可定位。
19. **`readback-empty` 是新增的失败原因**：有值位却读到空（典型是占位变成「请选择必填」）= 组件明确处在未选态，判失败。它和 `readback-mismatch`（读到了别的值）要分开看：前者是"没填上"，后者是"填错了/没提交"。
20. **`selectedCount()` 读的是组件自己的计数 span**（v2.0.17）：两套弹层都把「已选」和「1/1」拆成多个 span，拼起来是 `已选1/11`，整句正则会把限额读成 11 → 误判"没满" → 不去清空 → 点新项被拒绝。如果某个站点仍然出现"满额却没清空"，看报告里的 `attempts` 是否出现 `panel-readback-mismatch` + 计数相关线索。
21. **自定义字段的匹配规则**（v2.0.19 更新）：字段名走的是同一套标签匹配（精确 / 包含 / 字符相似 ≥ 0.78），并且**全局生效**——不管你把它加在哪个分类下，只要网页上出现同名标签就能对上。纯英文标签（`GitHub` / `WeChat` / `Email`）现在也能识别，但**仅限明确的 label 节点**（`<label>`、class 含 label/title 的元素）；如果某站把英文标签写成普通兄弟文本（`<span>GitHub</span>` 紧挨着 input），仍然认不出来。中文标签没有这个限制。
22. **自定义字段"重名"的代价是静默失效**（v2.0.19）：与内置字段重名 → 自定义那条被丢弃（内置优先）；同一分类下两个自定义字段同名 → 只有第一条生效。侧边栏会在输入时标红提示，报告里这类字段不会出现 `custom-no-match`（它们根本没进候选池）。**看到红字就改个名字**，别指望它会填。
23. **`custom-no-match` 的含义**（v2.0.19）：资料库里有这个自定义字段，这一页也确实出现了它所属的分类，但没有一个网页标签能对上。通常就是"字段名和网页标签措辞不一样"（网页写"微信"，你写"微信号"），改名字即可；也可能是那个字段在 iframe 里（见第 3 条）。
24. **"降级到年月"的判断依据是回读里没有"日"**（v2.0.18）：如果某站其实要日、但回读只显示到月（容器文本被截断之类），会被当成降级成功（状态=已填 + 说明里标「已按年月写入」）。这种少数情况以页面上实际显示为准。
25. **日期字段里的「仅年月」值**（v2.0.18 起对所有日期字段生效）：侧边栏显示成 `2020-09-01` 只是让日期控件能显示，资料库里仍是 `2020-09`；一旦你在控件里改了日期，存的就变成完整日期了。想表达"只知道月份"，就不要碰那个日期框。
26. **自动扩充只在"找得到明确按钮"时发生**（v2.0.20）：按钮文案必须带分类名（「添加教育经历」），或者是裸的「添加 / ＋」且位于最后一块之后。如果某站用的是纯图标按钮（没有文字）、或者把「添加」放在区块标题右侧，会**找不到按钮 → 只填第一段**，报告顶部那行会写「未能自动新增经历区块」。这时候把报告里那行发我，我按真实结构补选择器。
27. **扩充是"点一下就重扫全表"**（v2.0.20）：每次点击后整体重新扫描，最多 8 次。所以 N 段经历会带来 N-1 次全表扫描，页面上字段特别多时会明显变慢（每次约 0.5 秒等待渲染）。这是刻意的取舍——不重扫就会往已经失效的旧节点上填。
28. **「自动新增的块」在页面上的顺序由站点决定**（v2.0.20）：默认是新块追加在末尾，所以"资料库第 2 段 → 网页第 2 块"成立。如果某站把新块插在最前面，段的对应关系会错位（值不会串行，但会填进不同位置的块里）——报告里每个块都带 `#n`，一眼能看出来。
29. **日期面板"补点确定"可能误触**（v2.0.20）：面板没自行关闭时会去找文字为「确定 / 确认 / 完成 / OK」的按钮点一下。正常日历点完确定就等于提交，但如果某站的日历里还有个同名的「确定」用于别的用途（例如"确定清空"），可能适得其反。判据是**回读**：点完还是空就判失败并回滚，不会留下脏值。
30. **"一行两列"的字段行靠 label 数量配对**（v2.0.21）：只有当容器里**真实 label 节点数 == 控件数**时才按位置配对。如果某站两个字段共用一个 label（例如 `<label>起止时间</label>开始<input>~<input>`），配不上，仍会退回原来的打分逻辑，可能只填第一个。报告里看到某个字段"没记录/跳过"而页面上明显有值，就是这种情况。
31. **新增经历的块切分是启发式的**（v2.0.21）：找不到"签名一致的一组"时按父容器切块，要求每块 ≥3 个字段。如果某站新增的那段只有 1~2 个字段，切不开 → 两段会被并成 1 块（报告顶部那行会写"块数没变，但字段 x → y 个"）。看到这句就说明切分没成，把页面上那两段的字段列表发我。
32. **日期"键入优先"只对可编辑的纯文本框**（v2.0.21）：`phoenix-date-picker` 这类组件化控件仍走面板，因为硬写 DOM 值常常是"看着在、模型里没有"。判断依据是控件祖先类名里有没有 date-picker/calendar/select 之类特征；如果某站的可编辑日期框恰好带了 `select` 类名，会被当成组件化控件而走面板。
33. **月粒度适配的顺序是"先试日、再退月"**（v2.0.22）：永远是先按资料精度写，写不进去才退到年月。所以一个页面若只是"日被隐藏但仍存着"，你看到的会是 `2025-10`（回读只有年月），报告标「网页只到年月」。想确认网页到底存了什么，以页面回显为准。
34. **「添加」按钮找不到时的兜底是全文档搜分类名**（v2.0.22）：只会匹配文案里带"教育经历/实习经历/在校职务…"这类词的按钮。如果某站按钮写的是同义词（"增加一段学历"），既不在 `sectionKeys` 里也对不上 → 找不到按钮 → 只填第一段，报告顶部会写「未能自动新增经历区块」。
35. **纯图标按钮靠 `title/aria-label` 判断**（v2.0.22）：只有 `＋` 且没有 title/aria-label、类名也没有 add/plus 的按钮认不出来（无法区分"添加"和"展开"）。看到"没新增"就先确认这个按钮有没有可读属性。
36. **多分类轮流点，每次点完重扫全表**（v2.0.22）：每个分类单独计数、单独跳过，互不连累；总轮次上限 20。如果某站点了「添加」会滚动页面或弹层遮挡，可能影响后续分类的扫描结果——报告里每个分类各占一行，能看出断在哪。
37. **"两段共用一个父容器"靠标签重复周期识别**（v2.0.23）：要求每段 ≥3 个字段、各段字段数相差 ≤40%。如果新加的那段只有 1~2 个字段（例如只有"开始时间/结束时间"），切不开 → 仍会被并成 1 块。
38. **"第 2 条没填"先分清是渲染问题还是数据问题**（v2.0.23）：页面只渲染 1 段、资料库有 2 条时，插件会先点"添加"补出第 2 段。**如果页面第 1 段对应的就是资料库第 1 条**，而你把值填在了第 2 条，那第 1 段显示空是**正确行为**。判断方法：侧边栏当前显示的是"教育经历 N"，N 就是你在编辑的那一条；报告里每行都带 `#n` 标明是第几块。
39. **复合控件（1 个标签 + 类型下拉 + 值输入）**（v2.0.23）：标签只给"装值"的文本框，旁边的类型下拉不绑字段——所以它会在报告里留一条 `label-uncertain` 的行，这是预期的（类型通常已经是正确值）。如果某站的复合控件是"下拉在后面"，规则同样生效（取唯一的文本框）。
40. **名字像日期只是"写入方式"变了，不代表有值**（v2.0.23）：字段名含"时间/日期"会被强制按日期链路写，但**值仍然来自资料库**（schema 字段或自定义字段）。页面上有"毕业时间"而资料库没有对应值时，报告里是 `无记录`，不是 bug。
41. **网格布局的切块靠"标签重复"识别**（v2.0.24）：要求两段的字段名**至少 80% 一致**、每段 **≥3 个字段**。如果第 2 段字段名与第 1 段差异超过 20%（比如第 1 段叫"开始时间"、第 2 段叫"起始日期"且还有其他措辞变化），切不开 → 并成 1 块 → 第 2 段不填。**判据是报告里有没有 `duplicate-slot` 行**：有就说明没切开，把页面上两段的字段名列表发我。
42. **每段只有 1~2 个字段的经历切不开**（v2.0.24）：比如两段实习各只有"单位名称/实习地点"两个字段，总共 4 个字段，达不到周期切分的下限（≥6 个字段、每段 ≥3 个）。这种情况会并成 1 块，只填第 1 段，报告里同样会出现 `duplicate-slot`。这是刻意的：下限放低会把"一行两列"的普通字段行误当成两段经历。
43. **`duplicate-slot` 是提示不是错误**（v2.0.24）：它表示"这一段里出现了两个同名字段，我只填了第一个"。正常单段的表单不会出现；一旦出现，说明多段经历没切分干净，属于需要我按真实结构再调的情况。
44. **组件化下拉自带的搜索框会留一条 `label-uncertain`**（v2.0.25）：`phoenix-select` 内部那个 `<input class="phoenix-select_input">` 不是字段，标签已经明确不给它，所以它在报告里是一条"网页标签无法确定对应字段"。这是**预期**的，不是没填上。
45. **「精确命中优先」只对"选项文本完全等于别名"生效**（v2.0.25）：如果站点选项写的是「硕士学位」而资料里是「硕士」，仍走打分（约 0.9），此时若同时存在「双硕士学位」这一项，仍可能被判歧义。遇到就用自定义字段把值写成站点上的原文，或者告诉我站点选项全集，我把别名表补上。
46. **日期写成功后会自动收面板**（v2.0.25）：收面板的动作是"失焦 + Esc + 点一下页面空白"。如果某站的日历点空白处会**清空已选值**，就会前功尽弃（目前只在成功回读后才收，风险很低）。真遇到就告诉我，我改成只按 Esc。
47. **自定义字段的"加 / 改名 / 删"会同步到同分类的所有记录**（v2.0.26）：字段名按序号同步（第 i 行都是同一个字段），内容各填各的。所以删除时也会把所有记录上的这一行一起删掉——这是刻意的，保证"每条记录都有同一组字段"。
48. **与内置字段同名的自定义条目不再丢值，但内置优先**（v2.0.26）：候选匹配时仍然丢弃（避免同一标签命中两个槽），但读值时会去这条记录的 `__custom` 里找同名条目。如果某个值既填在正常字段里又填在自定义字段里，**正常字段的值优先**。
49. **每段只有 1~2 个字段的记录切不开**（v2.0.24 起）：自定义字段按记录取值的前提是块能切开。如果某分类每条记录只有 1~2 个字段（总共不到 6 个），切不开 → 只填第一条 → 报告里会出现 `duplicate-slot`。遇到就告诉我分类名和字段列表，我把下限再往下调一档。
50. **同槽冲突时"分类对得上"的优先**（v2.0.27）：页面上两处同名字段映射到同一个语义槽时，先写区块分类对得上的那处，另一处标 `duplicate-slot`。如果某站的正式表单区块**没有标题**（分类识别不出），它会被当成弱计划——若同时页面上还有别的区块有同名字段，正式表单那个反而填不上。看到 `duplicate-slot` 出现在"你确定该填的地方"，把诊断 JSON 发我。
51. **收尾复核只救"普通文本框"**（v2.0.27 / v2.0.28 改成最多重试 3 次）：写入后被站点清空的，文本/数字框会最多重试 3 次（越等越久）并标 `recovered-after-clear`；下拉、日期、上传不在这道复核里（它们各有回读校验）。如果看到 `cleared-by-site`，说明 3 次重写都没保住，需要按站点单独处理（把诊断 JSON 发我）。
52. **年月下拉面板按"点年再点月"处理**（v2.0.27）：面板里没有日/月格子、只有一个「2026年 10月」头时，先点头、再点目标年、点目标月。如果某站的年列表要滚动加载（2025 不在初始列表里），会滚动列表找（v2.0.29）；**滚动也找不到且头部年份不是目标年时，直接放弃点月**（attempts 里能看到 `ym-year-mismatch:2026`）——宁可跳过也不用旧年份提交错日期。
53. **年/月点选只认列表项，不认下拉头文字**（v2.0.29）：下拉头（「2026年 10月」）的子节点会被排除在查找范围外。如果某站把选项渲染在头部节点**内部**（极罕见），会点不到 → `ym-year:fail`，把诊断 JSON 发我。
54. **"一块塞两段"的切分认"标签重复周期 + 尾巴"**（v2.0.29）：两段字段顺序完全一致才切得开；尾巴（每段 ≤2 个的附加字段，如自定义 radio 组）按序轮流分给各段。如果第 2 段字段**顺序**和第 1 段不同（不是缺，是乱序），切不开 → `duplicate-slot`，把两段的字段名列表发我。

## 7. 建议的测试顺序

1. **先测个人信息**：只有 1 条记录，验证「性别 / 学历 / 最高学历 / 政治面貌 / 民族」这类枚举适配是否命中。这一层最容易判断对错。
2. **再测教育经历**：2 条记录、2 个网页块，验证开始/结束时间是否各归各位（这是本次重构的核心验收点）。顺便确认日期填到了日；如果网页只收年月，报告说明里应出现「已按年月写入」。
3. **最后测实习经历**：验证 `exp.start` 与 `edu.start` 不串。
4. **测一两个自定义字段**：在「个人信息」下加一条与网页标签同名的字段（例如网页上有「微信号」），看是否自动填上。**先看侧边栏有没有标红**：标红说明重名/没命名，这时填不上是预期行为。填不上且没标红，就把报告里的 `custom-no-match` 那一行连同「取到的标签」发我。
5. 每次都把「复制诊断」的 JSON 留一份，我来做定向校准。
